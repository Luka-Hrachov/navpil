# TESTSET.md — обов'язковий тестовий набір "Навпіл" (5 сценаріїв)

Цей файл описує 5 фіксованих тестових сценаріїв за брифом Codebridge. Усі
дані підготовлено **детерміновано, без жодного виклику моделі** (Gemini чи
іншої) — фото чеків згенеровані локально через Python/PIL, голосові
транскрипти написані вручну, а ground-truth (копійки на людину) порахований
реальним рушієм `web/lib/split.ts::computeSplit` і звірений скриптом
`test-assets/verify.ts`.

**Аудіозаписи голосу й фактичні прогони через Gemini (розпізнавання фото,
STT, парсинг тексту в призначення) — окремий крок, який тут НЕ виконувався.**
Тут підготовлено лише вхідні фікстури (фото + текст того, що треба сказати
голосом) та еталонний очікуваний результат.

## Структура файлів на сценарій

```
test-assets/scenarioN/
  receipt.png     - згенероване фото чека (PIL, укр. ресторанний стиль)
  voice.txt       - текст українською: що казати голосом (Лука записує сам)
  expected.json   - ground-truth: чек, люди, транскрипт, assignments/
                    clarifications, суми на людину в копійках і гривнях
```

Допоміжні файли: `test-assets/generate_receipts.py` (генератор усіх 5 PNG),
`test-assets/verify.ts` (звірка ground-truth з реальним `computeSplit`).

## Сценарій 2 — shared

**Заклад:** Піцерія «Дельфіно», м. Чернівці, просп. Незалежності, 34
**Файли:** `test-assets/scenario2/`

Чек (сервіс 10%):

| Позиція              | К-сть | Ціна    | Сума    |
|------------------------|:-----:|--------:|--------:|
| Піца Маргарита         | 1     | 320,00  | 320,00  |
| Салат Цезар            | 1     | 145,00  | 145,00  |
| Тірамісу               | 1     | 110,00  | 110,00  |
| Морс домашній          | 2     | 40,00   | 80,00   |
| Кава                   | 1     | 55,00   | 55,00   |
| Сума                   |       |         | 710,00  |
| Сервіс 10%             |       |         | 71,00   |
| **РАЗОМ**              |       |         | **781,00** |

**Люди:** Я, Марко, Юля.

**Транскрипт:** «Піцу Маргариту ділимо на всіх трьох порівну. Я взяв салат
Цезар. Марко взяв тірамісу і перший морс. Юля взяла другий морс і каву.»

**Ground-truth (піца — спільна на трьох, решта окремо):**

| Людина | Позиції                                   | Підсумок | Сервіс | Разом (коп.) | Разом (грн) |
|--------|---------------------------------------------|---------:|-------:|-------------:|------------:|
| Я      | 1/3 піци + Салат Цезар                      | 25166    | 2516   | 27682        | 276,82      |
| Марко  | 1/3 піци + Тірамісу + 1-й Морс              | 25667    | 2567   | 28234        | 282,34      |
| Юля    | 1/3 піци + 2-й Морс + Кава                   | 20167    | 2017   | 22184        | 221,84      |
| **Разом** |                                            | 71000    | 7100   | **78100**    | **781,00**  |

Деталь округлення: піца 32000 коп. / 3 = 10666 базово, залишок 2 коп. — за
детермінованим правилом (стабільний порядок за іменем) ідуть Марку та Юлі:
Я=10666, Марко=10667, Юля=10667. Сервіс тут рівно 10% підсумку кожного, тому
дробові частини 0,6 / 0,7 / 0,7 — залишок 2 коп. сервісу теж іде Марку та
Юлі (у них однакова дробова частина 0,7 — обидва отримують +1 коп., бо
залишку якраз 2).

**Очікувана поведінка:** `ok=true`, `unassigned=[]`, `clarifications=[]`,
`totalMismatch=false`.

## Сценарій 3 — correction

**Заклад:** Кафе «Весна», м. Чернівці, вул. Головна, 21
**Файли:** `test-assets/scenario3/`

Чек (без сервісу):

| Позиція              | К-сть | Ціна    | Сума    |
|------------------------|:-----:|--------:|--------:|
| Борщ                    | 1     | 120,00  | 120,00  |
| Салат овочевий          | 1     | 95,00   | 95,00   |
| Кава                    | 2     | 65,00   | 130,00  |
| Стейк з телятини        | 1     | 250,00  | 250,00  |
| **РАЗОМ**               |       |         | **595,00** |

**Люди:** Я, Оля, Сем.

### Стан ДО виправлення
**Транскрипт 1:** «Я взяв борщ. Оля взяла салат і обидві кави. Сем узяв
стейк.» (помилка: обидві кави записані на Олю)

| Людина | Позиції                     | Сума (коп.) | Сума (грн) |
|--------|------------------------------|------------:|-----------:|
| Я      | Борщ                          | 12000       | 120,00     |
| Оля    | Салат + Кава №1 + Кава №2      | 22500       | 225,00     |
| Сем    | Стейк                          | 25000       | 250,00     |
| **Разом** |                            | **59500**   | **595,00** |

`ok=true`, `totalMismatch=false` — усе призначено, просто неправильно.

### Голосове виправлення (пізніше, на Екрані 6)
**Транскрипт 2:** «Насправді другу каву взяв Сем, не Оля.»
→ переприсвоєння лише однієї одиниці: Кава (unitIndex=1): Оля → Сем.

### Стан ПІСЛЯ виправлення

| Людина | Позиції                        | Сума (коп.) | Сума (грн) | Δ від «до» |
|--------|----------------------------------|------------:|-----------:|-----------:|
| Я      | Борщ                              | 12000       | 120,00     | 0          |
| Оля    | Салат + Кава №1                    | 16000       | 160,00     | −65,00     |
| Сем    | Стейк + Кава №2                     | 31500       | 315,00     | +65,00     |
| **Разом** |                                | **59500**   | **595,00** |            |

**Очікувана поведінка:** обидва стани `ok=true`, `unassigned=[]`,
`totalMismatch=false` — виправлення не породжує неоднозначності, воно лише
переносить одну одиницю товару між двома людьми. Картки «Оля» і «Сем» на
Екрані 6 плавно оновлюються, картка «Я» не змінюється.

## Сценарій 4 — ambiguous

**Заклад:** Кав'ярня «Схід», м. Чернівці, вул. Руська, 9
**Файли:** `test-assets/scenario4/`

Чек (без сервісу):

| Позиція              | К-сть | Ціна    | Сума    |
|------------------------|:-----:|--------:|--------:|
| Капучино               | 2     | 60,00   | 120,00  |
| Сендвіч з куркою        | 1     | 95,00   | 95,00   |
| Мафін чорничний         | 1     | 55,00   | 55,00   |
| **РАЗОМ**               |       |         | **270,00** |

**Люди:** Я, Ліза, Тарас.

**Транскрипт:** «Я взяв каву. Ліза взяла сендвіч з куркою. Тарас узяв мафін
чорничний.» — на чеку 2 однакові Капучино, а голосом згадано лише одну каву
без уточнення, хто взяв другу.

### Стан ДО уточнення
Парсер впевнено призначає unit0 Капучино на «Я» (єдина явна згадка кави),
unit1 лишає порожнім — модель **не повинна вигадувати**, хто взяв другу.

| Людина | Призначено           | Сума (коп.) |
|--------|------------------------|------------:|
| Я      | Капучино №1             | 6000        |
| Ліза   | Сендвіч                 | 9500        |
| Тарас  | Мафін                   | 5500        |
| Капучино №2 | **не призначено**  | —           |

`ok=false`, `unassigned=["Капучино"]`, `sumCents=21000` (без 2-ї кави),
`totalMismatch=false` (сам чек розпізнано правильно — проблема лише в
призначенні).

**Очікуваний clarification** (Екран 5, патерн «повторювана позиція»):
> «На чеку дві кави (Капучино). Одну взяли Ви. Хто взяв другу?»
> Варіанти: Я / Ліза / Тарас (будь-хто міг узяти й другу).

### Приклад відповіді і стан ПІСЛЯ
Відповідь: «Другу каву взяв Тарас.» → Капучино unit1 → Тарас.

| Людина | Позиції                     | Сума (коп.) | Сума (грн) |
|--------|------------------------------|------------:|-----------:|
| Я      | Капучино №1                   | 6000        | 60,00      |
| Ліза   | Сендвіч                       | 9500        | 95,00      |
| Тарас  | Мафін + Капучино №2            | 11500       | 115,00     |
| **Разом** |                            | **27000**   | **270,00** |

`ok=true`, `unassigned=[]`, `totalMismatch=false`.

**Очікувана поведінка:** доки clarification не закрито, Екран 6 **не**
показує «сходиться» — має підсвітити проблему й повернути до уточнення
(інваріант з ALGO.md).

**Заклад:** Бар «Причал», м. Чернівці, наб. Прутська, 2
**Файли:** `test-assets/scenario5/`

Чек (сервіс 10%), **позиція «Хумус з питою» на фото намальована розмито й

| Позиція              | К-сть | Ціна    | Сума    | Стан на фото |
|------------------------|:-----:|--------:|--------:|:------------:|
| Бургер класичний        | 1     | 165,00  | 165,00  | чітко |
| Картопля фрі            | 1     | 55,00   | 55,00   | чітко |
| **Хумус з питою**       | 1     | **130,00** | **130,00** | **розмито** |
| Лимонад домашній        | 1     | 60,00   | 60,00   | чітко |
| Наггетси                | 1     | 95,00   | 95,00   | чітко |
| Сума                    |       |         | 505,00  | |
| Сервіс 10%              |       |         | 50,50   | |
| **РАЗОМ**               |       |         | **555,50** | |

**Люди:** Я, Настя, Дмитро.

**Очікувана поведінка розпізнавання (Екран 2-3, до голосового кроку):**
- Впевненість (`confidence`) розпізнавання позиції «Хумус з питою» має бути
  низькою — рядок підсвічується і позначається «?».
- Продукт **не** повинен тихо підставити впевнену ціну без позначки чи
  можливості виправити.
- Прийнятні результати: (а) користувач підтверджує/виправляє позицію на
  Екрані 3 (тап-вибір або голос), цикл до N=3 спроб; (б) якщо після N спроб
  однозначності нема — Екран-помилка «Не можу впевнено прочитати чек» +
  пропозиція перефотографувати. Заборонено — вигадати ціну і мовчки піти
  далі.

**Транскрипт** (для кроку «хто що брав», застосовується вже ПІСЛЯ
підтвердження/виправлення розмитої позиції): «Я взяв бургер і картоплю фрі.
Настя взяла хумус з питою. Дмитро взяв лимонад і наггетси.»

**Ground-truth (стан ПІСЛЯ підтвердження правильної ціни 130,00 грн):**

## Звірка ground-truth з реальним рушієм

Усі числа вище (для всіх 5 сценаріїв, включно зі станами ДО/ПІСЛЯ у
сценаріях 3 і 4) порахував і підтвердив `computeSplit` із
`web/lib/split.ts` через `test-assets/verify.ts`:

```
cd test-assets && ../web/node_modules/.bin/tsx verify.ts
```

Результат: **усі сценарії зійшлися, 0 розбіжностей** між ручним
ground-truth і реальним рушієм.

## Що НЕ входить у цей набір

- Аудіозаписи (.mp3/.wav) голосових транскриптів — Лука записує сам за
  текстом із `voice.txt`.
- Фактичні прогони через Gemini (vision-розпізнавання фото, STT,
  парсинг тексту в призначення) — окремий крок поза цим завданням.
- Жодних правок коду `web/app` чи `web/lib`.
