# Технічний стек — «Навпіл»

## Стек
- **Фронт + бек:** Next.js (React, TypeScript) — один репозиторій, повний full-stack.
  API-роути Next.js виконують серверну логіку (виклики моделей, розрахунок).
  Окремий Python/FastAPI бек НЕ потрібен.
- **Стилі:** Tailwind CSS + CSS-змінні з `DESIGN.md`.
- **Анімації:** Framer Motion (плавні, м'які).
- **Шрифти:** Satoshi (next/font/local) + JetBrains Mono (next/font/google).
- **Хостинг:** Vercel, безкоштовний Hobby. Push у GitHub → автодеплой → живий URL.
  Ключі моделей — у Vercel env vars (серверні, у браузер не потрапляють).

## Архітектура (головне рішення — за нього 80% оцінки)
Розрахунок часток — **детермінований код, НЕ модель.**
- **Модель робить лише 2 речі:**
  1. фото чека → структурований JSON (позиції, кількість, ціни, сервіс, підсумок);
  2. голосова фраза → структурована команда розподілу
     («позиція X — Ані», «страву Z ділимо втрьох», «друга кава — Сема»).
- **Код (детермінований) робить решту:** розподіл по людях, сервісний збір
  пропорційно, округлення за задокументованим правилом, усе в **копійках (int)**,
  перевірка інваріантів (сума сходиться, кожна позиція раз).

Це прибирає галюцинації цін і дає точні суми — рівно те, що перевіряють.

## Ролі моделей (уточнити ключ/вартість ПЕРЕД будь-яким прогоном)
- **Vision / OCR:** розпізнавання фото чека (напр. Claude або Gemini з баченням).
- **STT:** голос → текст (варіанти: Web Speech API безкоштовно, або Whisper/Gemini
  для якості й вимірюваної вартості).
- **TTS (опційно):** озвучення уточнень.
- **Розбір наміру:** голосовий текст → структурована команда (легка LLM-модель).

⚠️ За правилами Луки: перед будь-яким викликом моделі назвати ключ, кількість
викликів і суму — і чекати «так». На етапі скафолдингу викликів немає.

## Виміри (deliverable Codebridge)
Кожен крок (vision, STT, розбір наміру, TTS, повторні спроби) логувати окремо:
час + оцінка вартості за один чек/діалог. Хостинг рахувати окремо.
